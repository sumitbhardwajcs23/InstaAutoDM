1. MVP Scope & Goals
1.1 Objective
Ship a working, Meta-compliant Instagram automation tool that a single creator or small brand can connect in under five minutes, set up one comment-to-DM automation and one DM keyword auto-reply, and see it working on real traffic — in 4–6 weeks, with a two-person (or solo) team.
1.2 In-Scope Features
Account connect: OAuth login for one Instagram Professional (Business/Creator) account per user, linked to a Facebook Page.
Comment-to-DM automation: single keyword trigger on a post/reel → automatic private reply with a link or message.
DM keyword auto-reply: exact/contains keyword match on an incoming DM → canned text response.
Simple dashboard: connection status, automation rule list (create/edit/pause), conversation log, basic usage counter.
Free plan enforcement: 500–1,000 DMs/month hard cap with graceful stop + upgrade prompt.
Compliance guardrails: 24-hour window tracking, one private reply per comment, throttled sends.
1.3 Explicitly Out of Scope for MVP
Story mention/reply triggers (V1)
Multi-account support (V1 — MVP is single account per user)
AI-generated replies / GPT integration (V1)
Drag-and-drop flow builder, CRM integrations, team inbox, white-label (Pro)
Paid plans/checkout — MVP ships free-tier only; billing wiring is prepped but not turned on until V1
1.4 MVP Exit Criteria
The MVP is “done” when all of the following are true:
A real Instagram Business account can complete OAuth connect end-to-end without manual intervention.
A comment containing a trigger keyword reliably receives a private reply within a few seconds, with zero duplicate replies on retries.
A DM containing a trigger keyword reliably receives an auto-reply within the 24-hour window, and is silently skipped (logged, not sent) outside it.
The dashboard shows live counts that match what actually happened on Instagram.
10–20 beta users have run it for at least one week with no account flags or bans.

2. Meta App & Compliance Setup
2.1 Meta Developer App — Setup Steps
Create a Meta Developer account and a new app of type “Business” at developers.facebook.com.
Add the “Instagram” and “Webhooks” products to the app.
Create/link a Facebook Page, and connect an Instagram Professional (Business or Creator) account to it — personal IG accounts cannot use the Messaging API.
Configure OAuth redirect URIs for both local dev (e.g. ngrok HTTPS tunnel) and the production dashboard domain.
Request the permissions below and complete Meta App Review before going live with real (non-tester) accounts — budget 2–4 weeks for review, and start this in Week 1, not Week 11.
Complete Business Verification for the Meta Business account — required before advanced access to messaging permissions is granted.

2.5 Disclosure Requirement
Where required by applicable law, the automated experience must disclose that the user is talking to an automated system — at the start of the conversation, after a long pause, and at any handoff from bot to human. Bake a one-line disclosure into the default reply templates so users don't have to remember to add it.

3.2 Why a Queue, Even for MVP
Webhook delivery must be acknowledged quickly (Meta retries and can disable webhooks that time out or 5xx repeatedly). Separating “receive the event” from “process and send the reply” protects against slow downstream calls, lets you retry failed sends with backoff, and gives a single choke point to enforce the throttle in Section 6.5. This is worth the extra moving part even at MVP scale.

6. Core Feature Specifications
6.1 OAuth Connect Flow
User clicks “Connect Instagram” on the dashboard.
Backend redirects to Meta's OAuth dialog with the required scopes (Section 2.2).
User approves; Meta redirects back with an authorization code.
Backend exchanges the code for a short-lived token, then a long-lived Page access token.
Backend calls the Graph API to resolve the Instagram-scoped user ID and Page ID, and stores them encrypted in instagram_accounts.
Backend subscribes the Page to the messages and comments webhook fields.
Dashboard shows “Connected” and prompts the user to create their first rule.
6.2 Webhook Receiver & Event Processing
Single endpoint (POST /webhooks/instagram) handles both event types. Responsibilities, in order:
Verify X-Hub-Signature-256 against the raw body; return 403 and log on mismatch.
Persist the raw payload to webhook_events (cheap insurance for debugging and replay).
Push a job onto the queue with the event type and a stable dedupe key (Meta can send the same event more than once).
Return HTTP 200 immediately — all real work happens asynchronously in the worker.
6.3 Comment-to-DM Automation Logic


Figure 2 — end-to-end message flow for a single comment-to-DM automation
Implementation notes for the worker:
Idempotency first: before anything else, attempt an INSERT into comment_replies keyed on comment_id. If it conflicts, the comment was already handled — stop.
Case-insensitive matching: normalize both the comment text and the rule's trigger_keyword (lowercase, trim) before comparing.
7-day window: if the comment's created_time is more than 7 days old (e.g. a backfilled or delayed webhook), skip and log — Meta will reject the private reply anyway.
Send: POST to /{PAGE_ID}/messages with recipient.comment_id and the rule's reply_message.
On failure: retry transient errors (5xx, timeouts) with exponential backoff up to 3 attempts; do not retry 4xx errors such as window-closed or invalid comment — log as failed instead.
6.4 DM Keyword Auto-Reply Logic
On an inbound messages webhook, upsert the conversation row and set last_user_message_at to now.
Match the incoming text against active dm_keyword_reply rules for the account (same normalization as 6.3).
If a rule matches, send the reply via POST /{PAGE_ID}/messages with recipient.id set to the sender's IG-scoped ID.
If more than 24 hours have passed since the user's last message when a send is attempted (e.g. a delayed job), do not send — log as window_closed rather than error, since this is expected behaviour, not a bug.
Increment the account owner's dm_usage_this_period counter on every successful send, and check the free-plan cap before sending (Section 7).
6.5 Rate Limiting & Backoff Strategy
The worker enforces its own conservative internal ceilings, comfortably under Meta's published limits from Section 2.4, using Redis counters (sliding window, per instagram_account_id):

Meta's actual limit

Margin

1 private reply per comment_id, ever

When a job would exceed the internal ceiling, requeue it with a short delay (e.g. 30–60 seconds) instead of dropping or erroring — comments and DMs still get answered, just slightly slower during a spike. On any 4xx from the Graph API indicating a rate or policy violation, pause that account's automations for a cooldown period and surface a warning in the dashboard rather than continuing to retry blindly.

7. Free Plan Enforcement & Usage Metering
MVP ships with a single free tier: 500–1,000 DMs/month (pick 750 as the default; make it a config value, not a hardcoded constant, so it can be tuned or turned into a real paid-tier gate at V1 without a schema change).
Every successful outbound send (private reply or DM auto-reply) increments users.dm_usage_this_period.
Before sending, the worker checks the counter against the plan cap; if at or over the cap, the send is skipped and logged as usage_capped, and the dashboard shows an upgrade nudge.
A daily scheduled job resets dm_usage_this_period to 0 when usage_period_start rolls past one month — keep this job idempotent so a missed run doesn't double-reset.
Log usage_capped events distinctly from failures — they are a product signal (demand for a paid plan), not a bug.

9. Testing & QA Checklist
9.1 Functional
OAuth connect succeeds; disconnect fully revokes and cleans up local state
Comment containing the exact keyword (any case) triggers exactly one private reply
Same comment re-delivered by Meta (webhook retry) does not trigger a second reply
Comment older than 7 days is skipped, not sent, and is logged as such
DM keyword match sends within the 24-hour window; is correctly skipped outside it
Pausing a rule stops it from firing without deleting its history
9.2 Compliance
Webhook requests with an invalid/missing signature are rejected, not processed
Internal send ceilings (Section 6.5) never allow a burst above Meta's published limits, even under a simulated flood of comments
Default reply templates include the automated-experience disclosure line
9.3 Resilience
Graph API 5xx/timeout triggers retry with backoff, not an immediate failure
Graph API 4xx (e.g. window closed, invalid recipient) is logged and does not retry
Worker crash mid-job does not lose the job (queue persistence/ack semantics verified)
Token expiry is detected and surfaces a “reauth required” state rather than failing silently
9.4 Load
Simulate a viral post: a burst of 200+ comments in a few minutes against a test account, confirm the queue absorbs it and sends stay within internal ceilings

10. Deployment & Launch Checklist
Production environment variables set (DB, Redis, Meta app secret, encryption key for tokens) — nothing defaulted or hardcoded.
HTTPS confirmed on the public webhook URL; Meta app's webhook URL updated from the ngrok dev URL to production.
Meta App Review approved and the app switched from Development to Live mode.
Business Verification complete.
Error monitoring/alerting wired (even a simple Slack/email alert on repeated webhook failures or send failures).
Database backups enabled on the managed Postgres instance.
Privacy policy and terms of service pages published and linked from the OAuth consent flow (Meta requires this).
Beta user onboarding doc/video ready (Hindi + English) for the first 10–20 users.

C. Glossary


Term

Meaning

IG-scoped user ID

The identifier Meta gives an Instagram user, unique per app — not the same as their username

Private reply

A DM sent in response to a specific public comment, visible only to the commenter

Human Agent tag

A message tag that lets a manual (non-automated) reply go out up to 7 days after the user's last message

Idempotency key

A unique value (here, comment_id) used to guarantee an action happens at most once even if the trigger fires twice
